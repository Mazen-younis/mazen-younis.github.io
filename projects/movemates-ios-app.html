MY ROLE

University project: product concept, original branding, iOS interface and application, and supporting backend.

MoveMates is a sports community app that helps people discover activities, organise games and meet other players. I developed the native iOS experience, supporting API and original visual identity as part of my university iOS course.
01 / THE IDEA

The idea

Finding people to play sports with should not depend on already knowing the right group. I wanted to create a place where players could discover activities, meet people with similar interests and organise a game without unnecessary back-and-forth.

02 / THE EXPERIENCE

From discovering a game to joining the team

The application brings the core sports-community journey into one native mobile experience.

  • Discover and join: browse events, open activity details and request a place.
  • Organise a game: set the sport, location, date, time, number of players and skill preferences.
  • Manage participation: review requests and approve players as an organiser.
  • Build connections: create a player profile, exchange private messages and leave ratings.
03 / THE ENGINEERING

A native app with a dedicated backend

I built MoveMates with SwiftUI for the iOS interface and a Python/FastAPI service for the application's data and business operations. The client communicates with the API using URLSession and JSON, while SQLAlchemy maps the backend data to PostgreSQL.

  • SwiftUI: reusable views, navigation, forms and shared session state.
  • Application structure: separate models, view models, services and shared helpers.
  • REST API: routes for users, games, participation requests and private messages.
  • Device features: location-assisted activity creation and profile image selection.
04 / PRODUCT DESIGN

An identity of its own

MoveMates was also a design project. I created the name, logo and visual language, then carried that identity through the welcome experience, navigation and individual screens. The original app uses a dark interface with distinctive cyan accents.

Building the product from both sides made consistency especially important: every screen had to communicate clearly while remaining connected to the underlying data and interactions.

05 / THE OUTCOME

What I took from building it

The result is an academic, end-to-end application codebase that covers the main workflows of a sports community, from onboarding and event creation to join approvals, messaging and player feedback.

Designing the interface was only half the work. The real challenge was making the screens, application state, API and database fit together as one product.
PROJECT SCOPE

Built for a university iOS course. The public repository documents the source and design; it is not an App Store release or a production-hosted service. The published code has not been independently rebuilt or retested.
